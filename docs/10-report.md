## 1. なぜ CSV だけでは足りないか

電子帳簿保存法の**見読可能性**（施行規則第2条第2項第2号）は次を求める。

> 当該電磁的記録をディスプレイの画面**及び書面**に、整然とした形式及び明瞭な状態で、
> 速やかに出力することができるようにしておくこと

`docs/09-tax-research.md` 項目5 の調査で、この要件に対して**印刷可能な帳簿出力が
未実装**であることを確認している。CSV は「書面」の要件を満たす形ではない
（表計算ソフトで開いて印刷はできるが、それは利用者の環境に依存する）。

一方、税務職員のダウンロードの求めに応じる経路には**検索性のある形式**が要り、
PDF や画像だけでは認められない。つまり**両方要る**。

- **CSV** … ダウンロードの求めへの対応、他ソフトへの取り込み、利用者の再集計
- **印刷可能な形式** … 見読可能性（書面）

> **注意**: 優良な電子帳簿の適用を受けるかどうかは利用者の選択であり、
> 届出書の提出も利用者の作業である（`docs/09-tax-research.md` 項目5）。
> このソフトウェアが「要件を満たす」と名乗ることはしない（`CLAUDE.md` §10）。
> ここで言っているのは「**満たしうる形にしておく**」までである。

## 2. 出力形式の案

### 2-1. CSV

- 文字コードは **UTF-8 (BOM 付き)** を既定にする。BOM 無しだと Excel が
  Shift_JIS として開いて文字化けする（利用者が最初に踏む）。
  Shift_JIS 出力は**用意しない**——弥生連携で要求されたときに §6 で決める。
- 改行は CRLF（RFC 4180）。
- 金額は**桁区切り無しの数値文字列**（MCP の応答と同じ。`docs/07-mcp-server.md` §5）。
  Excel が勝手に数値解釈することは許容する（会計ソフトへの取り込みでは
  文字列のほうが安全なので、弥生形式は §6 で別途決める）。
- 1ファイル1帳簿。仕訳日記帳・総勘定元帳・試算表をそれぞれ別ファイルにする。

### 2-2. 印刷可能な形式は HTML にする（PDF にしない）

**PDF 生成ライブラリを依存に加えない。**

| 候補 | 却下/採用の理由 |
|---|---|
| **HTML（`@media print` 付き）** | **採用。** 依存ゼロ（文字列を組み立てるだけ）。ブラウザで開いて印刷すれば書面になり、画面表示も同時に満たす。日本語フォントの埋め込み問題が起きない |
| PDF（`printpdf` 等） | 却下。日本語を出すにはフォントを同梱するかシステムフォントに依存する必要があり、**バイナリ配布物に IPA フォント等を抱えるか、環境依存のフォント探索を書くか**の二択になる。会計の本質から遠い割に壊れやすい |
| Typst / LaTeX を呼ぶ | 却下。外部ツールの導入を利用者に強いる |

HTML なら `kaikei-report` が **`String` を返すだけ**で済み、テストも
文字列比較で書ける。

## 3. crate 構成: `kaikei-report` は I/O を持たない

```
kaikei-core / kaikei-policy / kaikei-app（既存）
        ↑
   kaikei-report   ← 追加。データ → 文字列 の変換に徹する
        ↑
   kaikei-cli（バイナリ）/ kaikei-mcp（既存）
```

**`kaikei-report` は `sqlx` にも `tokio` にも依存しない。** 入力は既に手元に
あるデータ（`Vec<JournalEntry>` / `TrialBalanceView` / `Statement` /
`LedgerPageView`）で、出力は `String`。

- DB から取ってくるのは呼び出し側（CLI バイナリ、または MCP ツール）の仕事
- そのぶん `kaikei-report` のテストは**DB を要らない**（`cargo test` が速い）
- `kaikei-e2e` が「実 DB → 出力」の通しを見る

`.github/workflows/architecture.yml` に「`kaikei-report` は `sqlx` / `tokio` に
依存しない」ステップを足す。**足したら必須チェックにも登録する**
（`CLAUDE.md` §13。ジョブを増やしても自動では追加されない）。

## 4. 出力の口: CLI と MCP の分担

| | CLI（`kaikei-cli`） | MCP ツール |
|---|---|---|
| 誰が使うか | 人間（確定申告の作業） | AI |
| 出力先 | ファイル | 応答（文字列） |
| 想定サイズ | 1年分の全仕訳（数千行） | — |

**帳簿の出力を MCP ツールにはしない**（少なくとも当面）。理由:

1. **応答に載せる量が帳簿の大きさに比例する。** 1年分の仕訳日記帳は数千行で、
   AI の文脈を食い潰す。`audit_log` は append-only なので、それが毎回残る
   （D-089 決定6 が読み取り系を要約させている理由と同じ問題が、もっと大きな
   規模で起きる）。
2. **出力の用途が「ファイルとして保存する」ことである。** 税理士に渡す、
   印刷する、他ソフトに取り込む——いずれも AI の応答を経由する必要がない。
3. CLI なら**出力先のパスを人間が決められる**。MCP サーバーにファイル書き込みの
   権限を与えると、信頼境界が変わる（現在は「DB に append する」だけ）。

代わりに、MCP からは**出力を起動できるようにしない**。人間が
`kaikei report journal --year 2026 --out ./out/` を叩く。

> **未確定**: CLI バイナリを `kaikei-report` の `[[bin]]` にするか、
> `kaikei-cli` を別 crate にするか。後者のほうが「report は I/O を持たない」を
> 構造で守れるが、crate が1つ増える。§7 の判断1。

## 5. 青色申告決算書のデータ出力

`JpStatementPolicy` が返す `Statement` は**汎用の様式**（区分と行）であって、
青色申告決算書の**欄**に対応していない。決算書に出すには、勘定科目を
決算書の各欄（売上（収入）金額、経費の各科目、貸借対照表の各欄…）に
マッピングする表が要る。

- マッピングは `kaikei-jp-data` の YAML に置く（税区分マスタと同じ扱い。
  コードに書かない）
- **どの科目をどの欄に入れるかは税務判断を含む**（`CLAUDE.md` §10）。
  同梱テンプレートの56科目については当てはめを用意するが、利用者が科目を
  追加した場合の欄は**利用者が決める**。未マッピングの科目は
  「どの欄にも入れず、一覧して知らせる」——黙って「その他」に入れない
- 出力は**データまで**（CSV / JSON）。**PDF の様式そのものは作らない**
  （国税庁の様式を模した帳票を出すのは、様式の正確さに責任を持つことになる）

## 6. 弥生インポート形式 CSV — **仕様を調べていない**

`ROADMAP.md` は「弥生インポート形式 CSV（優先度最高。税理士連携）」としているが、
**本設計案の時点で仕様を一次情報で確認していない。** 分かっていないのは:

- 列の定義と並び（借方/貸方の科目・金額・税区分・摘要・補助科目…）
- 文字コード（Shift_JIS か UTF-8 か）
- 消費税区分コードの対応表（弥生の区分コードと `kaikei-jp` の区分コードの写像）
- 「弥生会計」と「やよいの青色申告」で形式が違うか
- 仕訳日記帳形式（1行1仕訳）か振替伝票形式（1行1明細）か

**着手する前に弥生の公開資料で確認する。** 推測で列を並べると、取り込んだ側で
静かに科目がずれる——それは帳簿の誤りとして現れず、税理士が気づくまで残る。

税区分コードの写像は、`kaikei-jp` 側の区分（`SALES_10` 等）と弥生側の区分が
1対1で対応しない可能性がある。**対応しないものは変換せずエラーにする**
（黙って近い区分に丸めない）。

## 7. 判断が要ること（実装前に決める）

| # | 論点 | 案 | 影響 |
|---|---|---|---|
| 1 | CLI を `kaikei-report` の bin にするか、`kaikei-cli` を別 crate にするか | 別 crate（`kaikei-report` の無 I/O を構造で守る） | crate が1つ増える |
| 2 | 印刷可能な形式を HTML にしてよいか（PDF を作らない） | HTML | 「PDF が欲しい」なら方針が変わる |
| 3 | 帳簿の出力を MCP ツールにしないことの是非 | しない | AI に「決算書を CSV で出して」と頼めなくなる |
| 4 | 青色申告決算書の**様式そのもの**を出すか、データまでにするか | データまで | 様式まで出すなら国税庁の様式に対する責任が生じる |
| 5 | どの帳簿から作るか（優先順） | 仕訳日記帳 → 総勘定元帳 → 試算表 → 決算書 → 弥生CSV | 弥生CSV は §6 の調査が先 |
| 6 | 出力に**期首残高の欠落**を検出させるか | `get_statements` と同じ注記を CSV/HTML にも載せる | 載せないと、印刷した貸借対照表が黙って不完全になる |
